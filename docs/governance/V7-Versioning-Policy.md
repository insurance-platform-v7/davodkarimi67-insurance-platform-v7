# V7.0 Versioning Policy

## Semantic Versioning

The Insurance Platform V7.0 project follows Semantic Versioning (SemVer):

- MAJOR: incompatible API or contract changes.
- MINOR: backward-compatible functionality additions.
- PATCH: backward-compatible bug fixes and corrections.

## Pre-release Versions

Pre-release identifiers may be used when a version is not considered a stable release. Examples include -alpha, -beta, and -rc.

## Git Tags and Baselines

Git tags are used as repository version/baseline markers. Existing repository tags are historical baselines and must not be interpreted as current production releases unless supported by deployment/release evidence.

Current observed baseline tags include:


- v3-baseline
- v7-day01-baseline
- day51-baseline
- day52-baseline
- day53-baseline
- day55-baseline
- day58-baseline
- day59-baseline

A SemVer release must be supported by an explicit Git tag and corresponding repository/release evidence. A baseline tag alone does not establish a production release.

## Current V7.0 Status

No new V7.0 release tag is created by this policy document. Release/version claims must be based on verified Git and deployment evidence.
